# Financial PhraseBank LF 迭代框架

沿用同级 SMS 的分析、修改、聚合、评价和版本推进流程。以下为本任务的实现设定，不是已执行实验的结果。

## 任务与标注预算

从投资者视角判断单条英文金融新闻句子的情感：`0=negative`、`1=neutral`、`2=positive`，`-1` 表示 LF 弃权。关注明确的金融影响，不把一般情绪、营收和成本的上升统一判为正面。

使用清理后的 4,836 条样本。先按正文组、按原始类别比例留出约 20% 独立测试集，再抽取固定的 100 条标注集：负面 34 条、中性 33 条、正面 33 条。其余只保存编号和正文作为未标注数据。100 条是整个实验累计可用的金标预算，不是每轮新增 100 条。

种子 42。正文去掉空白后相同的记录不跨集合。首次运行生成三个划分及 `split.json`；后续只校验并重用，包括源 CSV 和各划分的哈希。标注版本级别与来源不作为特征。

## 每轮执行顺序

1. 用户指定起点 vN 及追加轮数。先评价起点；轮数为 0 时到此结束。
2. 运行 LF，三个集合分别产生投票矩阵。只在未标注矩阵拟合官方 Snorkel LabelModel：三分类、CPU、500 epochs、seed 42、均匀先验。均匀先验是默认假设，不是对真实类别比例的估计；34/33/33 的固定标注配额不能估计总体比例，也不使用源数据或测试金标校正先验。结果记录 `class_balance_source=uniform_assumption`，报告展示先验来源与限制。标注集和测试集仅使用这个模型预测，不重新拟合。
3. Analyzer 接收当前 LF 代码、完整固定标注集、未覆盖文本分组、LF 质量与独有/重叠覆盖，以及最近 5 轮实际改动和开发历史。向模型发送前保存 `feedback.json`，测试样本、标签、预测和指标不进入反馈。
4. Analyzer 同一次调用先在 `decision` 中选择本轮唯一操作类型，再按通用缺失模式分析并输出同类型的 `operations`，保留预计改变的标注样本、弃权边界和相关未覆盖组等字段。未标注集或标注集 LF 覆盖率严格低于 `LOW_COVERAGE_THRESHOLD` 时优先改善覆盖，必须在 `coverage_plan` 中说明覆盖缺口、改善方案和误标控制；允许修改已有 LF 扩展模式或新增独立模式，删除不能直接增加覆盖，低覆盖时优先删除须说明原因及后续方向。反馈同时提供各类别已覆盖/未覆盖数量。覆盖阈值只决定优先级，不作版本验收门槛。
5. 每轮将 Analyzer 原文交给独立的 JSON 格式检查修复 Agent，最多调用一次，仅修复 JSON 语法。只提供原文，不提供完整开发反馈；禁止增删改分析、操作、标签或编号。结果必须通过严格 JSON 解析及内容保留校验：合法原文保留结构和值；非法原文保留全部字段名和标量值的顺序。随后执行原有业务结构与引用校验；不合格即停止，不补造缺失字段。
6. Patcher 输出完整下一版 `lfs.py`，生成和技术修复都遵循已选操作类型和覆盖方案。AST 校验实际改动与建议完全一致；每个 LF 增、改、删各计一项，总计不能超过 `MAX_LF_CHANGES`，至少保留三个 LF。不允许通过共享常量、辅助函数、模块导入或 LF 间调用绕过上限。
7. 保存候选，运行、聚合、评价，按版本保存结果；写入改动记录与迭代汇总。
8. 以最新可运行候选作为下一轮起点。不设指标通过门槛，不因开发或测试指标下降自动回退。

`analysis.json` 保存通过格式检查与业务校验的决策和覆盖上下文，`changes.md` 记录本轮操作决策。Analyzer 原文保存在被分析版本的 `analysis_raw.txt`，格式 Agent 原文另存 `analysis_format_raw.txt`；合法 JSON 业务结构不符时另存 `analysis_invalid.json`。每轮的输入、原文、成功分析或错误还按运行批次保存在 `results/analysis_calls/<运行批次>/`，同一版本重跑不会覆盖旧批次。错误记录区分 Analyzer 与 `Analyzer JSON 格式检查修复` 阶段。

## 反馈样例

| 来源 | 样例组 | 上限 | 提供金标 |
| --- | --- | ---: | --- |
| 固定标注集 | 非弃权但预测错误 | 全部 | 是 |
| 固定标注集 | 聚合弃权 | 全部 | 是 |
| 固定标注集 | 预测正确 | 全部 | 是 |
| 未标注集 | 所有 LF 均未覆盖 | 最多 20 组，每组 2 个代表句 | 否 |
| 未标注集 | 两个或以上不同类别有票 | 10 | 否 |

三个标注分组合计为原有全部 100 条，不增加标注预算。未覆盖文本先将数字归一化，使用英文停用词及新闻套话/币种/单位停用词、1/2-gram TF-IDF 和 BisectingKMeans 按最大组优先二分。空特征文本隔离到 `kind=lexical_empty` 的小组；有效主题组的代表句只从有特征的文本中选择，先选余弦中心句，再兼顾相似性和差异性选其他代表句。每组记录平均余弦相似度、规模和关键词；低相似度表示词汇混杂，不能用两条代表句概括全部文本，更不能将组规模当作新 LF 预期命中数。默认 seed 42，样本较少时自动减少分组数，全为空词表时退化为单组。冲突样例仍按 seed 和版本名无放回随机抽取最多 10 条。

LF 反馈分别统计开发集和未标注集的独有覆盖数量、单 LF/多 LF 投票数量，以及每对 LF 的重叠、同票和冲突数量。独有覆盖为 0 不意味着 LF 无价值。

最近 5 轮历史仅查询当前版本及以前的相邻版本对，以代码 AST 提取实际增删改，忽略仅格式/说明变化；附最长 1600 字符的每项差异、当前开发指标及与上一版的比例差。只提取固定白名单中的开发和未标注统计，不传测试指标；不读取历史报告、整张迭代表或未来版本。缺失的版本对不补造数据。

另外从近期历史投票 CSV 中仅提取 `unlabeled` 行，找出当前全弃权、此前有票的文本，提供唯一文本总数与最多 10 个具体样例，字段为 `unlabeled_previously_covered`。旧票仅是覆盖回退线索，不是金标。提案应比较近期负收益改动与新模式的优先级；开发错误很少时，重点寻找能覆盖未标注文本的可复用模式，避免仅为保持开发集已覆盖准确率 100% 而持续收紧规则。

提案结构新增：`missing_pattern`、`action_rationale`、`expected_labeled_changes`、`abstain_conditions`、`unlabeled_group_ids`。预期样本只能引用本轮提供的固定标注集，投票值必须为整数 -1/0/1/2；分组只能引用本轮提供的组编号。若没有对应的标注样本或未覆盖组，可给空数组并说明原因；弃权边界必须提供。Patcher 同时接收这些设计约束。此处只校验提案结构与引用，不新增效果门槛或强制回退。

完整反馈在被分析版本的 `results/feedback.json` 保存，便于核对每轮输入。历史旧 `analysis.json` 无需改写，新字段从后续调用生效。

LF 只接收 `text` 字符串，不能读取文件、网络、环境变量、编号、金标、来源或一致性字段，不允许将整句抄成标签查表。需要正则时在目标 LF 内导入 `re`；规则应描述可复用模式。

## 失败与版本

语法、LF 接口、执行或投票值等技术错误反馈给 Patcher，最多额外修复一次。修复仍相对本轮原始代码计算 LF 改动数；两次均失败则停止并保留候选与错误。API 或文件系统错误直接停止，不交给 LLM 修改 LF。执行错误不包含可能来自测试集的样本正文或编号。

版本从 vN 依次生成 vN+1，不按指标挑选最佳版本。重新从旧版启动会覆盖对应后续版本。分析保存在被分析版本的 `analysis.json`，实际改动保存在新版本的 `changes.md`。

## 评价、用量与图表

每个版本分别记录开发与测试的覆盖率、全量/已覆盖准确率、三类 Precision/Recall/F1、Macro-F1 和三行四列的混淆矩阵。弃权在全量指标中计入真实类别的漏判。未标注数据只计算覆盖/冲突，不计算准确率或 F1。

聚合保留 SMS 的行为：允许最终预测与一致投票方向不同，不增加硬性多数票覆盖。三类冲突与聚合方向图均适配全部类别。

Analyzer、JSON 格式检查修复、Patcher、Patcher 修复四个阶段逐次记录 API 返回的 Token。每轮格式检查修复增加一次真实 API 调用，单列统计。无调用或未知用量显示为“—”，未知字段在 CSV 留空。本次与历史累计分开，离线验证不写为真实调用记录。

图表根据已有版本的结果生成五组 PNG/SVG：指标总览、三类指标、正确/错误/弃权构成、相邻版本变化、投票与聚合方向差异。单个版本没有相邻版本变化图。

固定的少量标注集指标是开发反馈，反复使用可能造成过拟合。测试指标只用于独立报告，不用于修改 LF、选择版本或决定追加轮数。
