# YouTube LF 迭代框架

沿用同级 SMS 的 WRENCH 固定划分导入方式，任务为 YouTube 评论垃圾检测。

1. 直接使用 WRENCH 固定提交 `d1185f6cfba8d5ace2a39229799cb3f1c136bf66` 的 `classification/youtube/train.json`、`valid.json`、`test.json`：train 1,686 条、valid 120 条、test 250 条。正文、顺序和样本归属逐条一致，不按原 CSV 重抽，不去重、不重新分组。
2. 标签为 `0=ham、1=spam`，LF 弃权为 `-1`。负面情绪、非英语和粗俗用语本身不构成垃圾评论；判断推广、自我引流、诈骗和无关广告。
3. 训练集只保存 `id,text`，验证集和测试集保存 `id,text,label`；编号是 `youtube_<split>_<官方编号>`。不导入官方训练金标或预定义弱标签。源文件及 CSV 的 SHA256、固定提交和条数写入 `data/split.json`；后续离线校验和复用，不静默重建。
4. 原 `youtube_spam.csv` 不参与当前实验。当前保留 WRENCH 固定划分下的 v1–v10、评估结果、汇总、Token 记录和图表；继续实验时从已有版本启动，从旧版追加会覆盖同名后续版本。
5. 起点由用户指定，先评价起点，再追加指定轮数。0 轮只评价，不调用 LLM；支持交互和命令行参数。
6. 每个版本执行 LF 得到 train/valid/test 投票矩阵；仅训练矩阵进入 Snorkel 拟合。二分类、CPU、500 epochs、seed 42、固定先验 `[0.5, 0.5]`。验证和测试仅用同一已拟合模型预测；其金标不参与模型拟合或先验估计。
7. Analyzer 接收当前 LF 完整代码、120 条验证集的整体指标、按类别已覆盖/未覆盖数量、训练覆盖/冲突统计及每个 LF 的质量。具体样例分五组，每组随机抽最多 10 条：验证错例、验证弃权、验证正确、训练未覆盖、训练冲突。按版本和种子可复现，训练样例不附金标、不作为已确认错例。
8. 测试正文、标签、预测和指标不进入 Analyzer/Patcher。没有历轮对话、分析或指标趋势输入；实际结构化输入保存到被分析版本 `results/feedback.json`。
9. Analyzer 同一次调用先在 `decision` 选择新增、修改或删除，再输出具体分析和同类型 `operations`。训练集或验证集 LF 覆盖率严格低于 `LOW_COVERAGE_THRESHOLD = 0.7` 时优先改善覆盖，必须提供覆盖缺口、改善方案和误标控制的 `coverage_plan`；可扩展已有 LF 或新增独立模式。删除本身不能增加覆盖，低覆盖时优先删除须说明理由和后续方向。阈值不是版本验收门槛。
10. Patcher 及技术修复遵循决策和覆盖方案，输出完整下一版 `lfs.py`。每轮默认只增、改、删一个 LF，至少保留三个；AST 校验实际操作与建议完全一致，不允许通过共享常量、辅助函数或导入绕过上限。
11. LF 是普通 `def lf_name(text)`，返回整数 -1/0/1；只允许局部文本处理，不访问文件、网络、环境变量、样本编号或金标，不将整句抄成标签查表。
12. 技术错误最多额外修复一次，修复仍相对本轮原始代码计数。两次失败停止并保留候选和错误；API/文件错误直接停止。错误反馈不包含测试正文或编号。
13. 每版记录验证和测试的覆盖率、全量/已覆盖准确率、两类 P/R/F1、Macro-F1 和混淆矩阵，以及训练覆盖/冲突和 LF 质量。全量指标包含弃权；LF 全弃权或聚合最高概率并列时保留 -1，导出为 `abstain`。
14. 以最新可运行版本继续，不因指标下降自动回退。测试指标仅用于报告，不用于 LF 修改、版本选择或轮数选择。
15. 从 vN 生成 vN+1；重复从旧版开始会覆盖对应后续版本。分析归被分析版本，改动和评价归新版本。`analysis.json` 保存决策和覆盖上下文，`changes.md` 记录决策；原始回复保存在 `analysis_raw.txt`，合法 JSON 结构不符时另存 `analysis_invalid.json` 并记录错误后停止。
16. `metrics.json` 保存 WRENCH 数据提交、集合条数和 CSV 哈希；绘图只使用与当前划分一致的结果，输出五组 PNG/SVG。单版本不生成相邻变化图。
17. 每次真实 Analyzer/Patcher/修复调用按 API 返回记录 Token，区分本次和历史，未知值留空；离线验证和零轮评价不计为 API 调用。

反复使用同一固定验证集可能对开发样本过拟合，最终效果由测试集报告。运行命令和实验起点说明见 `README.md`。
