# 风险标注错误模式分析报告（LLM版）

## 样本规模

- False Positive: 83
- False Negative: 5
- Type Mismatch: 209
- Score Diff Top: 200

## LLM 总结

- 误报集中在score_volatility和score_hack，大量无关内容被错误标记为行情波动或漏洞攻击风险，严重损害系统可信度。
- 大量真实风险事件（包括异常行情、监管、巨鲸等）被规则判定为“无明显风险”，主类别选取逻辑过于保守，导致类型缺失严重。

## 主要错误模式

### 1. score_volatility误触发异常行情波动 [false_positive]

- 影响 scorer: score_volatility
- 根因: score_volatility的关键词或语义特征过于宽泛，对‘比特币’、‘投资’、‘资产’等通用词触发波动关联，未排除观点/访谈/非市场类文本。
- 优先级: high
- 证据:
  - false_positive统计中异常行情波动风险出现32次，score_volatility触发36次，均值0.27，最大0.7
  - 样本220、595、864均为无风险访谈或AI新闻，但score_volatility达0.65，导致误判为异常行情波动风险
- patch 建议:
  - 增加否定上下文规则：排除仅包含观点表达、学习建议、AI进展等无实际价格波动的文本
  - 收紧触发条件：要求出现明确的价格涨跌幅度、百分比或‘暴跌/暴涨’等强波动词
  - 引入文本分类预过滤，对访谈、AMA、科普类内容降低波动得分上限

### 2. score_hack对无害企业新闻错误高分 [false_positive]

- 影响 scorer: score_hack
- 根因: score_hack的关键词过于宽泛，可能将‘攻击’、‘安全’、‘网络’等词汇泛化为攻击信号，对‘区块链’、‘加密货币’上下文过度敏感，未区分正常商业行为。
- 优先级: high
- 证据:
  - false_positive统计中链上漏洞/攻击风险出现15次，score_hack触发19次，均值0.175，最大0.95
  - 样本258（收购AI公司）、367（推出私人信贷基金）、315（稳定币需求）均与攻击无关，但score_hack高达0.95/0.92，被误判为链上漏洞/攻击风险
- patch 建议:
  - 收紧关键词：必须出现‘黑客攻击’、‘漏洞利用’、‘被黑’、‘安全事件’等具体恶意行为短语
  - 增加否定词/白名单：如出现‘收购’、‘信贷基金’、‘私人信贷’、‘贷款’等词时降低hack得分
  - 限制应用领域：仅对DeFi协议、交易所、智能合约相关安全事件触发，排除传统金融公司新闻

### 3. score_hack对真实攻击事件低分漏报 [false_negative]

- 影响 scorer: score_hack
- 根因: 真实攻击文本使用‘漏洞攻击’、‘坏账’、‘安全警钟’、‘量子计算威胁’等词汇，当前关键词库覆盖不足，且强度映射偏低；同时阈值可能设为0.5，导致0.4无法激活攻击风险。
- 优先级: high
- 证据:
  - false_negative共5条，gold全为链上漏洞/攻击风险，但规则判为无明显风险
  - 样本148、222、238、687、373均为DeFi漏洞攻击或量子计算威胁，score_hack最高仅0.4，部分样本甚至未触发
- patch 建议:
  - 扩展关键词：加入‘漏洞攻击’、‘坏账’、‘安全警报’、‘量子攻击’、‘社会工程攻击’、‘损失X万’等
  - 提高严重性映射：出现明确损失金额（如‘损失超1840万美元’）应给予0.8以上分数
  - 适当降低score_hack触发风险类型的阈值至0.3，确保真实事件不被遗漏

### 4. 风险类型缺失：主类别选取逻辑导致低分事件被忽略 [type_mismatch]

- 影响 scorer: score_volatility, score_regulatory, score_whale, score_macro, score_hack, score_liquidation, score_team, score_infra, score_solvency, score_stablecoin
- 根因: 风险主类别选择逻辑设置了最低分阈值（疑似0.5），低于此值即判定为‘无明显风险’，导致大量gold认可的低风险事件被错误归类。
- 优先级: high
- 证据:
  - type_mismatch总数209，top mismatch pairs包括异常行情波动风险→无明显风险58条、监管与法律→无风险51条、巨鲸→无风险35条
  - 样本中score_regulatory达0.35、score_macro达0.45、score_whale达0.45，但规则仍输出无明显风险，说明存在硬阈值
- patch 建议:
  - 移除或大幅降低风险类型输出的最低分阈值，改为若最高风险分>0即输出对应类型
  - 引入风险级别标签，如分数<0.3仍标记为‘低风险’但保留类型名，避免完全无类型
  - 为每个scorer设定0.1为最小触发阈值，确保细微风险信号能被捕获并标注类型

### 5. score_volatility和score_hack评分尺度严重偏离真实风险 [score_diff]

- 影响 scorer: score_volatility, score_hack
- 根因: 评分模型对非风险文本的特征空间存在高置信度映射，未做对抗校准，导致无关内容触发高分。
- 优先级: medium
- 证据:
  - score_diff分析中score_volatility触发48次，mean 0.146，max 0.808；score_hack触发48次，mean 0.155，max 0.95
  - 样本show无风险内容得0.65（volatility）、0.95（hack），真实攻击仅0.4，偏差巨大
- patch 建议:
  - 对score_volatility和score_hack重新校准强度曲线，使用标注数据训练回归模型或调整规则权重
  - 引入对抗样本测试集，确保中性文本得分低于0.2，高风险事件得分普遍高于0.5
  - 设置分数上限，非强信号最高不得超过0.4

## Scorer 级诊断

- **score_volatility**: 过宽触发
  - 原因: 在false_positive中触发36次，将访谈、观点、AI趋势等非市场内容判为异常行情波动，得分均值0.27，最高0.7，说明无实际价格波动时也能触发。
  - 建议: 收紧关键词，要求出现具体涨跌幅度；增加否定上下文，排除无行情数据的新闻；引入文本分类预过滤。
- **score_hack**: 过宽触发 + 漏召回
  - 原因: 误报：对收购、信贷基金等无害新闻给出0.95高分；漏报：真实攻击（如漏洞利用、坏账）仅得0.4，甚至未触发。统计中false_positive触发19次，false_negative5次中3次触发但分低。
  - 建议: 区分方向：收紧误报关键词（排除‘收购’、‘信贷’等），扩展真实攻击关键词（‘漏洞攻击’、‘损失金额’），提高损失场景的分数映射，适当降低分类阈值。
- **score_regulatory**: 主类别竞争失败
  - 原因: false_positive中触发12次（均值0.107），type_mismatch中监管风险被忽略51条，样本显示触发0.35但未输出，说明阈值过高。
  - 建议: 降低分类所需的最低分阈值，使0.3以上的监管信号能被标记为监管风险。
- **score_whale**: 过宽触发
  - 原因: false_positive中触发10次（最大值0.75），将普通DeFi产品介绍误判为巨鲸行为；同时也存在巨鲸事件被忽略（type_mismatch 35条），但低分时未被采纳。
  - 建议: 收紧触发条件，要求明确提及大额转账/地址，排除产品说明类文本；适当降低分类阈值以捕获低分真实巨鲸事件。
- **score_macro**: 主类别竞争失败
  - 原因: false_positive中触发11次，但type_mismatch中宏观风险被忽略16条，样本显示score_macro达0.45仍未输出类型。
  - 建议: 降低分类阈值，如0.3以上即可标记为宏观风险，同时排除纯观点引述。
- **score_liquidation**: 强度映射偏高
  - 原因: score_diff中触发21次，均值0.076，最大值0.75，样本999中分数0.75导致规则高分，但gold仅45；也有无风险内容得0.45被误判为爆仓风险。
  - 建议: 校准分数映射，确保仅明确清算事件（如强制平仓、链上清算）给予高分，中性金融产品介绍降低得分。
- **score_fraud**: 强度映射偏高
  - 原因: false_positive中触发7次，样本884、935虽为诈骗新闻，但gold认为严重程度低（score 10-25），规则却给出88分，夸大风险。
  - 建议: 根据诈骗金额、受害者规模调整分数上限，避免历史旧案或小额诈骗获得过高评分。
- **score_team**: 证据不足
  - 原因: 在所有误报/漏报/type_mismatch中均未触发，难以判断问题。
  - 建议: 持续监控，必要时补充关键词。
- **score_infra**: 证据不足
  - 原因: 未触发记录，但type_mismatch中有基础设施异常被忽略8条，可能完全未命中。
  - 建议: 检查关键词覆盖，补充协议层异常的相关模式。

## patch 顺序

- Step 1: score_volatility 误触发
  - 动作: 收紧触发关键词，要求明确价格波动描述，添加否定上下文（如‘访谈’、‘建议’、‘AI趋势’）降低得分，设置非市场内容得分上限为0.2。
  - 收益: 大幅减少false_positive中异常行情波动风险的误报（当前32条），提升准确率。
- Step 2: score_hack 双向修复
  - 动作: 区分误报场景和真实攻击：对‘收购’、‘信贷基金’等无害词降权或否定；扩展真实攻击词库（‘漏洞攻击’、‘损失’等），提高损失事件分映射至0.8以上；降低分类阈值至0.3。
  - 收益: 同时减少false_positive（15条）和false_negative（5条全部），解决最突出的误报/漏报矛盾。
- Step 3: 主类别选取逻辑
  - 动作: 移除硬阈值，改为若最高风险分>0即输出对应风险类型，可附加风险级别（低/中/高），不再出现‘无明显风险’覆盖有信号事件。
  - 收益: 立即解决type_mismatch中209条事件类型缺失，显著提升系统覆盖面。
- Step 4: score_regulatory / score_macro / score_whale 阈值与关键词
  - 动作: 将这三个scorer的分类阈值调至0.2-0.3，同时收紧score_whale关键词以减少误报，score_regulatory和score_macro增加地缘政治/政策文本的覆盖。
  - 收益: 减少type_mismatch中监管（51）、巨鲸（35）、宏观（16）的漏标，同时控制误报。
- Step 5: score_volatility和score_hack的强度校准
  - 动作: 利用标注数据集，对抗训练或规则调优，确保中性文本得分<0.2，高风险事件得分>0.5，减少score_diff极端偏差。
  - 收益: 整体评分更符合真实风险量级，降低score_diff top200的偏差。

**整体置信度**: medium
