# 风险标注错误模式分析报告（LLM版）

## 样本规模

- False Positive: 133
- False Negative: 2
- Type Mismatch: 180
- Score Diff Top: 200

## LLM 总结

- 规则系统最大问题是score_hack过宽触发导致大量假阳性（特别是将非安全新闻误判为链上漏洞/攻击风险），同时多个scorer（volatility、regulatory、whale、macro等）覆盖不足，造成大规模类型错配和漏判。
- 此外，score_regulatory强度映射偏高、score_liquidation存在误关联，以及score_team/score_infra几乎完全不触发，进一步拉大分数偏差并降低系统覆盖率。

## 主要错误模式

### 1. score_hack滥用触发链上漏洞/攻击风险 [false_positive]

- 影响 scorer: score_hack
- 根因: score_hack的关键词（如漏洞、攻击、黑客）过于宽泛，未能区分背景引用与实际事件，且缺少否定词或上下文过滤，导致大量‘提及型’文本被误判为严重攻击风险
- 优先级: high
- 证据:
  - FP样本中48条规则主类别为‘链上漏洞/攻击风险’（占比最高），52条金标为‘无明显风险’
  - score_hack在FP中触发50次，均值0.245，最大值0.95，例如新闻283（公司买币）被评0.85，新闻315（稳定币需求）被评0.8856，均无实际安全事件
  - 多例FP单纯因背景提及‘漏洞’、‘黑客’等词导致高分，如新闻904提及Drift Protocol漏洞，导致score_hack高达0.9497
- patch 建议:
  - 收紧score_hack关键词触发条件：要求同时出现资产损失、合约地址、具体协议等实体词才给高分，仅背景提及则降权
  - 增加否定词列表（如‘未受影响’、‘预防’、‘过去’、‘历史漏洞’）并匹配否定句式以跳过背景性描述
  - 引入金额门槛：内容中需明确提及损失金额>阈值（如10万美元）方可进入中高风险区间
  - 对明确否认或澄清类表述（如‘不会用于’、‘没有记录’）降低分数

### 2. 严重安全事件未能有效激活score_hack [false_negative]

- 影响 scorer: score_hack
- 根因: score_hack对部分真实攻击事件的触发力不足，可能因用词偏离典型关键词（如‘社会工程攻击’、‘内部热钱包’）或金额表述未达到阈值规则，导致分数偏低甚至零分
- 优先级: high
- 证据:
  - 漏报2例均为‘链上漏洞/攻击风险’，规则均判为‘无明显风险’
  - 新闻238（Rhea Finance漏洞损失1840万）仅触发score_hack 0.3178，总分32导致低风险标签
  - 新闻687（Zerion被盗10万）所有scorer均未触发，score_hack为0
- patch 建议:
  - 扩充score_hack的语义匹配，覆盖‘社会工程’、‘内部钱包被盗’、‘未经授权转账’、‘保证金交易功能被利用’等表述
  - 降低对小规模攻击的金额门槛要求，或引入‘事件定性’关键词（如‘被盗’、‘损失’）即可给出中等基础分
  - 增加对‘漏洞攻击’、‘事后分析’等后续报道的识别，避免因上下文稀释而漏判

### 3. 多数风险类别因scorer覆盖不足被误判为无明显风险 [type_mismatch]

- 影响 scorer: score_volatility, score_regulatory, score_whale, score_macro, score_liquidation, score_team, score_infra
- 根因: 多个scorer的关键词库严重滞后，缺失常见市场表述、监管讨论、大户行为、地缘事件等核心触发词，导致即使金标认定为该类风险，规则侧也无法生成相应分数
- 优先级: high
- 证据:
  - 类型错配中171条规则主类别为‘无明显风险’，而金标覆盖异常行情(58)、监管(35)、巨鲸(30)、宏观(14)等多种风险
  - 具体样本：异常行情（news 8‘最大痛苦点’、news 765‘波动加剧’）、监管（news 397‘CFTC批评’）、巨鲸（news 482‘大户准备出售’）、宏观（news 272‘霍尔木兹海峡开放’）均未触发对应scorer
  - 样本中相关scorer分数几乎全部为0，如score_volatility、score_whale、score_macro大量未触发
- patch 建议:
  - score_volatility：增加‘价格回落’、‘挤压’、‘波动’、‘支撑缺失’、‘信任危机’、‘升级态势’等市场动荡表述
  - score_regulatory：扩展至‘国会批评’、‘拟议规则’、‘监管阻力’、‘法案推进’等非执法类监管动态，并设定中等分数
  - score_whale：加入‘大户’、‘持仓变动’、‘准备出售’、‘鲸鱼’等正面词语，同时减少对赔偿、补贴等金额的误触发
  - score_macro：覆盖‘地缘政治’、‘原油’、‘停火’、‘封锁’、‘通胀传导’等宏观冲击词
  - score_liquidation：增加‘期货清算’、‘爆仓’、‘强平’等词，但要避免与纯宏观新闻混淆
  - score_team/score_infra：急需大规模补全项目治理、手续费异常、团队抛售、协议层异常等关键词

### 4. 强度映射偏高与主类别错误导致分数严重偏离 [score_diff]

- 影响 scorer: score_regulatory, score_liquidation, score_whale
- 根因: score_regulatory对‘监管’类新闻几乎无差别给予最高分，缺乏强弱分级；score_liquidation关键词与能源、石油等词无冲突过滤，容易误关联；score_whale对金额高度敏感而忽略上下文，导致主类别选择错误后进一步拉大分数差
- 优先级: medium
- 证据:
  - score_diff大的样本中，score_regulatory多次给到0.8高分（如news 704、176、873），但金标风险分仅25，造成大分差
  - score_liquidation在宏观能源新闻（news 815）给出0.75高分，导致主类别错判为‘爆仓/清算’，与金标‘宏观/政策冲击’冲突
  - score_whale在OneCoin赔偿新闻（news 884）给出0.75，而实际为诈骗/跑路风险，主类别竞争失败
- patch 建议:
  - score_regulatory：区分执法/处罚（高）与政策讨论/澄清（低），设置不同强度档位
  - score_liquidation：加入否定条件，当上下文出现‘能源’、‘石油’、‘封锁’等宏观词时降低或禁止清算类高分
  - score_whale：将金额触发与‘转账’、‘移动’动词强绑定，并排除赔偿、冻结等被动场景
  - 优化主类别选取逻辑：当多个scorer分数接近时，优先选择语义更贴合的金标类型（可通过规则模板辅助），或引入二级分类器进行二次校准

## Scorer 级诊断

- **score_hack**: 过宽触发
  - 原因: 在FP中触发50次，均值0.245，大量无关新闻（增持BTC、稳定币需求）因提及‘漏洞’、‘黑客’等词被打到0.85+，导致假阳性主类别；同时真正严重漏洞又出现漏报，说明触发不够精准
  - 建议: 收紧关键词匹配逻辑，要求同时出现损失金额、协议名称等实体，增加否定词和背景过滤，降低背景引用的强度；对‘被盗/被攻击’事件给予更高基础分但避免过敏感
- **score_regulatory**: 强度映射偏高
  - 原因: FP样本中触发40次，均值0.17，但在多例监管讨论/澄清新闻中给出0.8最高分，造成与金标巨大分差；同时类型错配显示其漏掉许多监管讨论新闻（如CFTC主席国会批评），说明阈值不统一
  - 建议: 建立监管严重性分级：执法/诉讼/罚款→高分，政策讨论/提案/澄清→中低分；扩大关键词覆盖范围以召回更多监管动态
- **score_volatility**: 漏召回
  - 原因: 类型错配中58例异常行情被漏判，样本显示‘最大痛苦点’、‘情绪波动’、‘升级态势’等均未触发；FP中虽然有虚假触发但主要由meme币极端涨跌引发，整体覆盖率不足
  - 建议: 大幅扩充行情波动关键词，纳入常见市场术语和情绪描述，同时加入防止纯价格播报过度触发的门控（如要求波动幅度/引述分析观点）
- **score_whale**: 漏召回
  - 原因: 错配中30例巨鲸风险未触发，真实大户行为（持仓准备出售、矿企卖币）未激活；反而在诈骗赔偿新闻中因金额数字误触发，说明关键词不全面且无上下文校验
  - 建议: 补充‘大户/鲸鱼/持仓变动/准备出售’等正面词，对金额触发强制要求伴随‘转移/移动/存入’等动作词，排除‘赔偿/退款’等被动场景
- **score_macro**: 漏召回
  - 原因: 错配中14例宏观风险未被识别，地缘新闻如‘海峡开放’、‘停火’、‘原油价格’等均无触发，说明几乎无实用关键词
  - 建议: 构建宏观冲击词库（地缘冲突、制裁、石油、通胀、加息、封锁等），并区分重大事件与一般报道，可结合外部地缘指数辅助
- **score_liquidation**: 主类别竞争失败
  - 原因: 在偏差样本中常被触发且分数较高，但有时被错误选为主类别（如宏观能源新闻被误判为爆仓），表明与其他scorer竞争时缺乏有效的消歧机制
  - 建议: 增加领域词典，当上下文中出现‘石油’、‘能源’、‘地缘’等词时降低清算类权重；同时确保其仅对期货、杠杆强平内容高分
- **score_fraud**: 证据不足
  - 原因: 触发统计较少（FP 6次，但样本中OneCoin赔偿被whale盖过），未能明显体现误判模式，但可能也存在类似过宽或漏报问题
  - 建议: 目前优先处理其他高频问题，后续根据小样本补充调整
- **score_team**: 漏召回
  - 原因: 偏差样本中项目治理/团队异常（如手续费操纵、项目方抛售）完全未触发，导致高分差漏判
  - 建议: 立即补充团队行为异常关键词：手续费调整、手动参数修改、项目方出售、内部操作等，并赋予中等风险分
- **score_infra**: 漏召回
  - 原因: 与score_team类似，基础设施异常样本未被捕获，几乎零触发
  - 建议: 扩充协议层异常关键词，如Gas异常、预言机操纵、Layer 2故障等
- **score_outage**: 证据不足
  - 原因: 触发极少，暂无明确错误样本
  - 建议: 暂不修改，持续监控
- **score_solvency**: 证据不足
  - 原因: 触发数少，未发现明显模式
  - 建议: 暂不修改
- **score_stablecoin**: 证据不足
  - 原因: 仅触发1次，样本不足
  - 建议: 暂不修改

## patch 顺序

- Step 1: score_hack
  - 动作: 收紧触发条件：增加否定词表（未受影响、预防、历史等）和实体需求（损失金额>10万或具体协议），降低纯背景提及的强度系数
  - 收益: 减少约48例假阳性中的大部分，同时修复漏报问题中的低分情况，大幅提升精确率
- Step 2: score_volatility、score_regulatory、score_whale、score_macro
  - 动作: 扩充关键词库覆盖漏报项，同时为regulatory建立严重性分级（执法>政策讨论）
  - 收益: 解决约150例类型错配中的漏召回，恢复对行情、监管、巨鲸、宏观新闻的正确分类，召回率显著上升
- Step 3: score_liquidation、score_whale的关联逻辑
  - 动作: 增强上下文过滤（如禁止能源词汇引发清算分，要求动作词绑定金额触发）
  - 收益: 减少主类别错误导致的分数偏差，改善部分大分差案例（如宏观被误判为爆仓）
- Step 4: score_team、score_infra
  - 动作: 从零构建关键词库，覆盖项目治理异常、团队抛售、手续费操纵等场景
  - 收益: 填补当前完全盲区，避免重要项目异常完全漏报
- Step 5: 主类别选取逻辑
  - 动作: 当多个scorer接近时，引入规则模板根据文本语义优先选择更可能类别，或降低次要scorer的竞争权重
  - 收益: 进一步减少score_diff中的类别误判，提升整体对齐度
