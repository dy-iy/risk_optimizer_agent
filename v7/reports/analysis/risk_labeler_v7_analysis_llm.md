# 风险标注错误模式分析报告（LLM版）

## 样本规模

- False Positive: 137
- False Negative: 1
- Type Mismatch: 200
- Score Diff Top: 200

## LLM 总结

- score_hack 对“漏洞”“攻击”等词过度敏感，是误导报（FP）的首要驱动力，大量无风险或次要提及被误标为高风险。
- score_team、score_infra 等类别完全未触发，导致项目治理/团队异常、基础设施异常等真正风险被系统性漏报。

## 主要错误模式

### 1. score_hack 对“漏洞/攻击”的过度触发 [false_positive]

- 影响 scorer: score_hack
- 根因: score_hack 关键词匹配过于简单，只要出现“漏洞”“攻击”即给出高分，未区分历史事件、他人批评与当前实际风险。
- 优先级: high
- 证据:
  - 误报样本中 score_hack 触发49次（触发占比最高），平均值0.1857，最大0.95。
  - 样本ID 315（稳定币需求）仅因文中提及 Drift Protocol 漏洞被 score_hack 评为0.92。
  - 样本ID 904（USDC 政策）因提及“Drift Protocol 漏洞”得分0.95。
  - 样本ID 283（公司增持比特币）触发 score_hack 0.85，文中无实际攻击。
- patch 建议:
  - 对“漏洞”“攻击”等词增加否定/背景语境限制，例如前有“因...漏洞遭到批评”“此前...漏洞”时不触发。
  - 引入最小金额门槛或损失结果要求，仅当描述当前直接损失或新发现的漏洞时才给出高分。

### 2. score_macro 对宏观讨论的宽泛触发 [false_positive]

- 影响 scorer: score_macro
- 根因: score_macro 对“降息”“油价”“政策”等词触发阈值过低，未考虑内容是否真正构成冲击风险。
- 优先级: high
- 证据:
  - 误报样本中 score_macro 触发36次，平均0.1227，最大0.55。
  - 样本ID 273（美联储降息概率）仅降息预期就被评为0.55。
  - 样本ID 876（油价冲击分析）是前瞻性市场分析，被评为0.55。
  - 样本ID 266（AI合规融资）与宏观政策几乎无关，仍触发 score_macro 0.45。
- patch 建议:
  - 增加触发条件：仅当明确提到“冲击”“危机”“大幅波动”等强语气词才给予较高分。
  - 引入否定词列表：“预期”“概率”“不太可能”等修饰词削弱强度。

## Scorer 级诊断

- **score_hack**: 过宽触发 + 漏召回
  - 原因: 误报触发最多，对‘漏洞’一词反应过强；同时漏掉了 AI 社会工程攻击等新型黑客方式。
  - 建议: 区分历史提及与当前攻击，增加否定语境；扩充关键词库，纳入新型攻击术语。
- **score_macro**: 过宽触发
  - 原因: 对降息概率、油价分析等宏观讨论给出偏高评分，导致大量误报。
  - 建议: 仅对负面冲击性言论给高分，引入否定词限制。
- **score_volatility**: 过宽触发 + 漏召回
  - 原因: 普通市场新闻（ETF申请、交易量新高）被误标，但真实波动风险（如最大痛苦点、信任危机）却漏报。
  - 建议: 加强对‘异常’强信号的依赖，扩展专业术语覆盖。
- **score_regulatory**: 过宽触发 + 漏召回
  - 原因: 官员中性讲话被误标为监管风险，但韩国犯罪活动等真正风险未触发。
  - 建议: 区分行动性词汇（起诉、罚款）与陈述性词汇（推动、咨询），并添加负面行为关键词。
- **score_whale**: 过宽触发 + 漏召回
  - 原因: 对大额转账一律高分，但漏掉抛售、解锁等巨鲸行为。
  - 建议: 细化触发条件，针对‘抛售’‘清仓’‘解锁’等增加专项规则。
- **score_team**: 漏召回
  - 原因: 触发数0，所有项目团队/治理异常风险均未被识别。
  - 建议: 新增关键词和语义模式，如‘CEO更换’‘团队大量出货’等。
- **score_infra**: 漏召回
  - 原因: 触发数0，基础设施异常如手续费飙升、预言机错误完全未捕获。
  - 建议: 添加协议层关键词，如‘手续费调至1280倍’‘预言机故障’等。
- **score_liquidation**: 过宽触发
  - 原因: 对含‘仓位’‘清算’的财经分析文章也触发，造成误报。
  - 建议: 限定于已发生/迫在眉睫的强平事件，非假设性评论。

## patch 顺序

- Step 1: score_hack
  - 动作: 增加否定语境规则（如‘因...遭批评’时降低权重），同时扩充攻击关键词（社会工程、热钱包被盗等）。
  - 收益: 直接减少约 49 次误报触发，并覆盖唯一的漏报案例。
- Step 2: score_team 与 score_infra
  - 动作: 从零建立触发逻辑，加入‘项目方出货’‘团队异常’‘手续费调至异常’‘预言机故障’等关键短语。
  - 收益: 弥补项目治理与基础设施类风险的系统性漏报，降低 type_mismatch 和 score_diff 中的高分偏差。
- Step 3: score_macro 与 score_regulatory
  - 动作: 收紧触发条件：macro 仅回应‘冲击’‘危机’等强信号；regulatory 排除‘推动监管’等中性表述，增加‘犯罪’‘调查’等真实行动词。
  - 收益: 减少 gold 无风险→规则监管/宏观类别的错配。
- Step 4: score_whale
  - 动作: 补充‘抛售’‘清仓’‘解锁’等巨鲸行为词，并对普通大额转账设置更高金额门槛或语境过滤。
  - 收益: 提升巨鲸类别的召回率，同时降低过宽触发的误报。
- Step 5: score_volatility
  - 动作: 扩展专业关键词（如最大痛苦点、轧空），并引入强波动信号分级，避免普通市场描述高分。
  - 收益: 改善异常行情类别的漏报与误报平衡。
