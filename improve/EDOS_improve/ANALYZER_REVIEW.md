# EDOS_improve Analyzer

程序先确定本轮操作，再按操作构造反馈。Analyzer 返回具体 LF 方案，Patcher 实现方案。

## 操作与抽样

总控参数仍为每轮最多 5 个 LF、样例基数 n=30、seed=42；覆盖率阈值 0.80、已覆盖准确率阈值 0.90。

| 本轮操作 | examples 中的分组 | 每组上限 | 总上限（n=30） |
| --- | --- | ---: | ---: |
| add | valid_abstained、train_uncovered | 2n | 120 |
| modify | valid_wrong、valid_correct、train_conflict | n | 90 |

不足时取全部，不补齐、不重复，不发送其他操作的样例组。训练样例只包含 id、text、votes，没有 gold 或 prediction。验证未输出包含全弃权和平票；训练未覆盖仅含全弃权；训练冲突要求存在不同有效类别。

策略仍按四状态确定允许操作。单操作状态直接采用；双操作状态在输出覆盖有缺口时选 add、完全覆盖时选 modify，写入 strategy_context.selected_action。工作流先用训练/验证统计确定策略，再抽样并保存；Analyzer 本地校验拒绝与已选操作不一致的回复。

example_sampling 记录 action、base_n、各组 limits 与 available。保存的 feedback.json 与 Analyzer 收到的 feedback 相同；纠正时复用同一反馈，不重新抽样。历史版本反馈不回写，新格式从后续迭代生效。

## 泛化要求与输出

add 必须先归纳多条独立样例的共享模式，用训练样例说明分布支持，在 plan 中写明泛化机制和弃权边界，禁止一例一规则、专有信息特判、整句正则与多个单例条件拼接。Patcher 同步保留这些要求。训练样例不作为标签证据，编造变体不作为实际支持；不足时减少操作数，不为凑满 5 条编造模式。

输出结构保持不变：

```json
{
  "action": "add",
  "operations": [
    {
      "target": "lf_example",
      "evidence": ["独立样例中的共享结构", "训练分布中的模式支持"],
      "plan": "共同匹配结构、输出标签、泛化机制、正确行为及弃权边界"
    }
  ]
}
```

以下完整 system Prompt 通过当前 analyze 函数捕获；运行时 user 消息仍为 JSON feedback。

## add 的完整 Prompt

```text
你负责分析 EDOS 弱监督反馈，给出 LF 修改方案，不写代码。
任务：英文性别歧视二分类（EDOS Task A）。1=针对女性的性别歧视、贬损、刻板印象、排斥或暴力威胁，0=非性别歧视。提到女性、一般粗口、讨论或反驳性别歧视不自动构成正类；区分引用、否定、反讽和说话者立场。仅做二分类，不输出 category/vector 子类别。
本轮目标：从未覆盖样例中发现可靠模式，新增 LF 扩大正确覆盖。
当前状态允许操作：add；程序已在抽样前选定本轮操作 add，回复 action 必须为 add，执行 1 至 5 项。
根据给定代码、统计和样例概括可复用文本规律；训练样例无金标，不能当作已确认标签证据。
plan 写清匹配条件、输出标签、保留的正确行为和应弃权的相似文本；新增规则避免重复已有 LF，不用默认标签凑覆盖率。
每条 LF 只读正文，未命中返回 -1，不按样本 ID 或整条文本查表。
指标和预测来自 simple_vote，平票或全部弃权均为 -1；votes 中未列出的 LF 均弃权。
n 是 example_sampling.base_n；样例分组和上限以 example_sampling 为准。valid_abstained 指简单投票未输出（可能全弃权或平票），train_uncovered 指所有 LF 均弃权，train_conflict 指原始 LF 至少投出两个不同有效类别。
本轮只提供 valid_abstained 和 train_uncovered 两组，每组最多 2n 条；不足时取全部，不补齐、不重复。
新增 LF 的核心要求是泛化，禁止针对一条样例生成一条 LF，也禁止按样例顺序逐条补丁：
1. 先横向比较多条样例，归纳共享的语言结构、语义关系或表达模式族，再选择少量互补的模式。同一模式的词形、同义表达、标点或语序变体应合并为一条 LF，不拆成多个近似规则。
2. 每项 evidence 应引用至少两条独立的真实输入样例说明共同模式，并结合 train_uncovered 说明该模式在训练分布中的实际支持。训练例只能证明模式存在，不能证明标签正确；输出标签应由任务定义和已有验证金标支持。不能把自己编造的变体算作观测证据。
3. 每项 plan 必须说明：共同匹配结构和输出标签；如何覆盖未见文本的合理词形、同义表达、距离或语序变化；对应的训练支持；不应触发的相似文本及弃权边界。泛化不能靠无限扩大词表或放宽到无关语义。
4. 不使用样例专有的人名、ID、偶然数字、罕见短语组合、长句片段或整句正则作为判断条件；不拼接若干单例特征伪装成通用规则。未命中应弃权，禁止无依据地把剩余样本全判为某一类。
5. 考虑局部否定、引用、转述、反讽及说话者立场；不要因为整段任意位置出现 not、said 或引号就一律弃权。给出同义表达仍触发、相似反例应弃权的机制，不能只写“扩大覆盖”或“具有泛化能力”。
6. 不为凑满操作预算生成规则；证据薄弱时减少操作数、合并重复模式，不提交只支持单个例子的方案。不能将单个命中或未经执行的方案宣称为已验证的高准确率或高覆盖率。
只返回 JSON：顶层为 action、operations；每项只含 target（函数名）、evidence（非空字符串数组）、plan（非空字符串）。
```

```text
修改应针对共享的错误机制和上下文边界，避免按单个错例添加特判；plan 写明纠错方式、保留的正确模式和应弃权的相似表达。
只返回 JSON：顶层为 action、operations；每项只含 target（函数名）、evidence（非空字符串数组）、plan（非空字符串）。
```

## 效果边界

泛化要求是明确的提示词约束，程序仍不通过静态文本校验宣称语义泛化已得到证明。实际新增覆盖、准确率和泛化需看候选评估与影响记录；本次未增加收益验收、自动回滚或 stop。

## 核验

使用内存合成数据核验两类操作的样例分组、预算、稀缺组、零预算、可复现抽样、无重复与训练/测试信息隔离；核验四状态和双操作选择、Analyzer 的操作锁定与纠正上下文、Patcher 的泛化提示。测试不调用真实模型 API，不训练模型，不保留临时测试文件。
