# 风险标注错误模式分析报告（LLM版）

## 样本规模

- False Positive: 188
- False Negative: 13
- Type Mismatch: 199
- Score Diff Top: 200

## LLM 总结

- 规则系统在监管、波动、巨鲸、黑客四个维度存在严重过宽触发，导致大量无害新闻被误报为高风险，尤其以政策声明、常规市值报告和大型机构购买最为突出。
- 黑客攻击类漏报严重，score_hack在真实攻击事件中得分过低甚至完全不触发，而“漏洞”提及的语境判断缺失，同时波动与巨鲸类别在主类别竞争中错配频繁。

## 主要错误模式

### 1. 监管、波动、巨鲸三大scorer过宽触发 [false_positive]

- 影响 scorer: score_regulatory, score_volatility, score_whale
- 根因: 这些scorer关键词过于宽泛，缺少否定词/排除语境，且未区分常规市场数据、机构行为与真正风险事件；金额阈值过低或强度映射偏高。
- 优先级: high
- 证据:
  - false_positive中监管与法律风险误报64例、异常行情波动55例、大额转账/巨鲸37例，占误报的83%
  - 样本675（巴基斯坦解除禁令）触发score_regulatory=0.8被标为高风险，gold为无明显风险
  - 样本220/6/133（市值报告）触发score_volatility≈0.66被标为波动风险，gold为无明显风险
  - 样本820（闪迪纳入指数）、670（摩根士丹利ETF购买）触发score_whale≥0.75被标为巨鲸风险，gold为无明显风险
  - trigger_scores统计：score_regulatory触发79次(mean 0.21)、score_volatility触发61次(mean 0.20)、score_whale触发42次(mean 0.17)
- patch 建议:
  - score_volatility: 增加对“总市值”、“24小时交易量”、“占有率达”等模板化市场报告的排除规则，仅对大幅异常波动或剧烈抛售/拉升触发
  - score_whale: 提高金额阈值（如单笔>1亿美元），排除ETF购买、上市公司购入、个人净资产持仓等中性描述，加入否定词如“购入”、“ETF”、“资产管理公司”
  - score_regulatory: 增加否定模式库（如“解除禁令”、“裁定…不属于证券”、“允许…”），降低此类新闻得分，仅对起诉、罚款、禁令、监管调查等负面事件给出高分

### 2. 黑客攻击scorer严重漏召回，真实事件得分过低 [false_negative]

- 影响 scorer: score_hack
- 根因: score_hack的关键词匹配过于有限，未覆盖“利用”、“攻击”、“盗取”等常见攻击描述，且即使触发，基础得分也过低，导致综合评分无法提升；同时误报中的高值来自不相关上下文，说明缺乏语境否定。
- 优先级: high
- 证据:
  - false_negative统计中gold primary type为链上漏洞/攻击风险共13例，占漏报绝大多数
  - 样本444（Drift 2.7亿美元被利用）rule_risk_score=0，top_triggered_scores为空；样本899（LLM路由器漏洞窃取50万美元）同样完全不触发
  - 多处真实攻击（如238 Rhea Finance损失1840万、426 Hyperbridge损失250万）score_hack仅为0.3，rule_risk_score=30，被标为low，而gold为high
  - trigger_scores统计：score_hack在漏报中触发10次，mean_value仅0.23，max 0.3，远低于误报中的max 0.98
- patch 建议:
  - 大幅扩充攻击类关键词（如“攻击”、“利用漏洞”、“盗取”、“损失金额”、“遭受攻击”、“黑客”、“被黑”），并根据金额提及提升基础分
  - 提高默认基础得分，使类似事件至少达到70分以上，避免被标为low
  - 增加否定语境规则，过滤“追回”、“冻结”、“报告漏洞”、“不受影响”等表述，防止误报

### 3. 波动风险漏归与巨鲸风险误归双向错配 [type_mismatch]

- 影响 scorer: score_volatility, score_whale
- 根因: score_volatility对部分真实波动新闻（如价格下滑50%、Meme币市值短时大涨）不敏感，阈值设置偏高或关键词缺失；而score_whale虽然过宽触发，但又在某些巨鲸行为（如大户准备出售、转移大额BTC）上触发不足，存在两个方向的阈值偏差。
- 优先级: high
- 证据:
  - type_mismatch中“异常行情波动风险→无明显风险”共56例，排名第一；“无明显风险→大额转账/巨鲸行为风险”42例，排名第二；且“大额转账/巨鲸行为风险→无明显风险”18例，显示双向错配
  - 样本2/332/340：均被gold标为波动风险，但rule标为无明显风险，且top_triggered_scores为空
  - 大量巨鲸行为的金标（如482/645/841）被规则判为无明显风险，表明score_whale对某些巨鲸描述不敏感
- patch 建议:
  - 调低score_volatility对价格大幅波动（如≥30%涨跌）的触发阈值，并增加波动描述关键词（“飙升”、“暴跌”、“滑落”）
  - 对score_whale既需要提高金额阈值减少误报，也需要增加对“转移至钱包准备出售”、“抛售”、“大户准备卖出”等行为模式的检测，弥补漏召回
  - 调整主类别选择逻辑：当多个scorer触发时，优先考虑有实际负面后果的类别，而非仅凭高分抢占

### 4. 清算scorer对“清算风险”中性描述过度敏感 [false_positive]

- 影响 scorer: score_liquidation
- 根因: score_liquidation对“清算”一词绝对敏感，无论上下文是“降低清算风险”还是“清算价”，均视为高风险，缺乏对“降低…风险”等正面/中性描述的否定。
- 优先级: medium
- 证据:
  - false_positive中有8例误报为清算风险，但score_diff中liquidation触发33次，mean 0.13
  - 样本87（Fluid推出aWETH赎回协议以降低清算风险）triggered score_liquidation=0.85，gold为无明显风险
  - 样本563（英国资管公司推出代币化基金）gold为监管风险，rule误标为清算风险并触发liquidation=0.85
  - 样本350（Hyperliquid多单清算价）gold为清算风险，rule正确但score_liquidation=0.82，但此例是正确触发，问题在于误报样本中也出现高分
- patch 建议:
  - 引入否定短语规则：如“降低清算风险”、“避免清算”、“清算保护”，将此类匹配得分大幅降低
  - 仅对明确发生大规模清算或爆仓事件触发高分，可结合“清算头寸”、“X亿美元清算”等强烈信号

## Scorer 级诊断

- **score_regulatory**: 过宽触发
  - 原因: 在79次误报触发中，mean值0.21，但频繁将解除禁令、法律裁定等正面/中性政策新闻标为高风险；样本表现如巴基斯坦解除禁令、JENNER不属证券等均被误报。
  - 建议: 增加否定模式库（解除、允许、不视为、裁定…不属于），并对非负面政策声明降分，保留高分给起诉、罚款、禁令调查等。
- **score_volatility**: 过宽触发 + 漏召回
  - 原因: 对常规市值/交易量报告给出~0.66高分，导致大量无明显风险新闻被误标为波动风险；同时type_mismatch中56例真实波动风险被标为无明显风险，说明对实际价格波动新闻的捕获不足。
  - 建议: 增加排除模板（总市值、24小时交易量、占比），同时降低对大幅涨跌描述的分值门槛，补充“暴跌”“飙升”等波动关键词。
- **score_whale**: 过宽触发
  - 原因: 42例无明显风险被标为巨鲸风险，均值0.17但误报样本往往高达0.75；大量ETF购买、机构持仓等中性大额交易被标为风险，而部分真实巨鲸准备出售反而漏报。
  - 建议: 提高金额阈值，排除机构/ETF购买、净资产投资等描述；增加卖出/转移准备的关键词，并优化主类别竞争逻辑。
- **score_hack**: 漏召回 + 过宽触发
  - 原因: 漏报13例黑客攻击，且触发时max仅0.3导致rule_risk_score低至30，而误报样本中却出现0.98的高分，说明关键词区分度差。
  - 建议: 重构关键词：扩充攻击特性词，提升基础得分至70+；增加否定语境过滤追回/修复/漏洞报告等非风险情况。
- **score_liquidation**: 过宽触发
  - 原因: 对“降低清算风险”等防护性描述打出0.85高分，导致误报，同时正确识别清算事件时也会高分，但缺乏语境区分。
  - 建议: 增加否定短语如“降低清算风险”“避免清算”，对防护性描述降低得分，仅对大规模爆仓/清算事件维持高分。
- **score_fraud**: 证据不足
  - 原因: false_positive中仅7例触发，false_negative中未触发，样本不足无法判断主要问题。
  - 建议: 持续监控，待有更多误报/漏报样本后再分析。
- **score_macro**: 证据不足
  - 原因: 触发极少（3次误报，1次score_diff），影响范围小。
  - 建议: 暂不调整，保持观察。
- **score_outage**: 证据不足
  - 原因: 误报和漏报均极少，样本不足。
  - 建议: 暂不调整。
- **score_solvency**: 证据不足
  - 原因: 触发极少，误报3例，无明确模式。
  - 建议: 暂不调整。
- **score_stablecoin**: 证据不足
  - 原因: 仅1次误报触发，无显著模式。
  - 建议: 暂不调整。
- **score_team**: 证据不足
  - 原因: 从未触发，可能存在盲区但缺乏样本。
  - 建议: 需收集更多样本后评估。
- **score_infra**: 证据不足
  - 原因: 从未触发，同样证据不足。
  - 建议: 暂不调整。

## patch 顺序

- Step 1: score_volatility 和 score_whale 的过宽触发
  - 动作: 为volatility添加市值/交易量/占比报告排除规则，提高触发阈值；为whale增加机构购买/持仓排除词，提高金额门槛（如>1亿美元）
  - 收益: 大幅减少误报数量，波动和巨鲸误报合计92例可降低50%以上
- Step 2: score_hack 的漏召回和过宽触发
  - 动作: 扩充攻击事件关键词库，将基础得分提升至70-90，并增加否定语境（追回/报告/不受影响等）过滤误报
  - 收益: 基本消除黑客攻击漏报，误报高分的修复提及类新闻也会大幅下降
- Step 3: score_regulatory 的语境区分
  - 动作: 建立负面/中性词库，对“解除”“允许”“不视为”等降权，仅保留高负面影响的关键词给高分
  - 收益: 监管误报减少约一半，保持对真正处罚/禁令的敏感度
- Step 4: score_liquidation 的触发条件精细化
  - 动作: 加入否定短语保护，仅对“发生清算”“爆仓金额”等真实负面事件高分
  - 收益: 清算相关误报明显减少
- Step 5: 主类别选择逻辑
  - 动作: 在多scorer竞争时，根据金标边界优化权重，例如当score_volatility仅由常规报告触发则降级为无明显风险，当score_whale金额不足或行为中性时降级
  - 收益: type_mismatch中的波动漏归和巨鲸误归改善，总体类别准确率提升

**整体置信度**: high
