# Crypto：加密货币新闻风险标注

主程序按阶段拆为 [init.py](init.py)、[analyzer.py](analyzer.py)、[patcher.py](patcher.py) 和 [orchestrator.py](orchestrator.py)。`data/` 保存两个 CSV 和[数据集说明](data/README.md)；`artifacts/` 保存配置、提示词与数据清单；`tools/` 的职责见[工具说明](tools/README.md)；`versions/` 保存规则、候选和报告。

## 1. 数据集构成

当前训练集 **56 条**、测试集 **15 条**。来源为 `workflows/v4/data/crypto_news_train.csv` 的 1,000 条新闻。 从复核后的 1,000 条候选中，按标签下采样删除 929 条，再按标签组合分配约 80%/20%；训练、测试各自的非零类别数量最大/最小不超过 **3:1**。相同文本整组分配，不跨集合；seed 只用于同标签组合内的稳定排序。数量与比例详见 [数据说明](data/README.md)。

标注类型是 **12 类风险多标签分类 + 风险等级三分类**。类别例如“链上漏洞 / 攻击风险”“监管与法律风险”“稳定币异常风险”；等级为 `low`、`medium`、`high`。示意：`{"categories": ["链上漏洞 / 攻击风险"], "level": "high"}`。

稳定币异常风险仅有 2 条，严格限制每侧各类最多相差 3 倍后只保留 71 条新闻。原数据参与过历史规则迭代，当前测试指标仅作兼容性对照。

## 2. 初始 LF 怎么构建

从零构建时，每个风险类别生成一个 LF，共 **12 个**（`lf_01` 至 `lf_12`）。从训练集按 seed=42 打乱后，每个标签最多选 3 条样例，将各标签样例、本任务标注说明和 LF 设计提示交给 LLM，每次生成一个指定函数。生成后检查语法和接口；格式或代码校验失败时携带反馈重试一次。LF 运行时只接收 `text` 和 `inputs`，不接收金标或样本 ID；命中返回 `labels`、`reason`，不确定则返回 `None`。 本任务还必须返回风险等级 `level`。

每个 LF 先判断风险事件是否成立，再给出等级，处理否定、条件句和观点表达。新建规则取命中类别并集和最高等级；全部弃权时输出空类别和 low。也可导入已有规则作为首版；旧 Crypto 脚本保留只读辅助函数与原聚合逻辑，续跑直接加载已接受版本。

## 3. 如何评价 LF 的质量

单个 LF 统计触发次数、覆盖率（触发样本数 / 总样本数）和触发时标签精度（正确投票标签数 / 投票标签总数），标记从未触发的函数；未触发时精度未定义。整体检查未覆盖样本数。另统计每个 LF 的等级与文档金标等级一致率；文档等级不是单个风险类别的独立等级金标，该值只作诊断。

聚合后训练集质量分为：

`Q = 0.25 × 类别 Micro-F1 + 0.25 × 类别 Macro-F1 + 0.20 × 等级 Macro-F1 + 0.10 × high Recall + 0.20 × high F1`

候选必须使 Q 严格提升；上述五项指标允许的最大下降依次为 **0.02、0.02、0.03、0.30、0.03**，均为绝对差值。结合等级混淆矩阵，分别检查类别漏报、误报和高风险等级错误。

训练集用于生成样例、定位错误、修复 LF 和决定是否接受候选。测试集只在本次迭代决策结束后评估，不向模型提供测试样例、错例或指标，不影响重试及版本选择。每个保存的脚本（包括候选）同目录下的 `report.md` 同时列出训练集和测试集指标；任务总 `report.md` 和 `script_metrics.csv` 汇总全部脚本。单 LF 诊断基于原始投票，版本接受依据训练集聚合预测。

## 4. 主程序与运行方式

| 主程序 | 职责 |
| --- | --- |
| `init.py` | 从训练样例逐个生成 LF，校验后保存 `versions/v1/rules.py`；不做迭代修改 |
| `analyzer.py` | 根据某版本的训练错例输出修改建议，保存到 `versions/vN/reports/analysis/analysis.json` |
| `patcher.py` | 读取匹配当前脚本和数据的分析，只替换指定 LF；候选保存到 `versions/vN/reports/patch/attempt_N/` |
| `orchestrator.py` | 串联初始化、训练评估、分析、修改、质量比较、重试、接受版本和最终测试报告；负责续跑 |

在本任务目录中运行完整流程（自动从当前已接受版本继续；无版本时创建首版）：

```powershell
python orchestrator.py --iterations 1
```

尚无版本时只生成首版：

```powershell
python init.py
```

按需单独分析和修改已保存版本：

```powershell
python analyzer.py --version v1
python patcher.py --version v1
```

单独运行 `patcher.py` 只保存候选，不推进已接受版本；总控负责自动版本选择。总控在 `versions/iterations/` 保存自己的迭代候选。各入口支持 `--help`；模型调用配置仍来自项目根目录 `.env`，token 继续累计到本任务账本。

## 数据准备与重新开始

数据准备由 `tools/data.py` 完成，多数类下采样与分层分配一起求解；数据读取时再次校验两侧类别比例与文本隔离。准备新快照需要 SciPy（已加入根目录 requirements.txt）；运行现有 CSV 不依赖求解器。

当前已清空旧规则、候选、报告、检查点、token 账本和历史归档。运行 `python orchestrator.py --new --iterations 1` 将重新生成 v1 并迭代一轮，指标与 token 从头记录。首轮完成后，去掉 `--new` 即可继续迭代。数据、配置、提示词和流程代码均保留。
