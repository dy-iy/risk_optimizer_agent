# FinNSP 子任务：针对实体的负面消息判定：LF 构建方案

0 和 1 各建一个 LF。正类需要负面事实或指控与候选实体相关；负类需有证据的无关、澄清或非负面结构。实体和负面词共现只是线索。多个候选时不能只检查第一个，不确定则弃权。

## 公共接口

- 函数为 lf(record)，输入仅包含 text 和 inputs，无 gold、样本 ID 或来源元信息。
- 命中返回 labels、reason；Crypto 另含 level；不命中返回 None。
- 样例来自 train，不通过 ID 或全文记忆作答。
- 生成后先运行并评估，再交给 Analyzer 定位问题；Patcher 只替换选中的现有 LF。
- 不允许修改聚合器、数据加载和评分工具。

## 分析重点

结合二分类混淆、正类 F1、候选数量、明确提及的候选与否认线索，区分负面漏报、主体错配和否认误读。分析范围不扩展为主体抽取评分。

## 接受条件

Macro-F1 严格提升，正类 F1 最大下降 0.02。原始行第 3 列为文本、第 4 列为实体、第 5 列为二分类标签；混入的 negative 表头已排除，未改成 1；无候选实体记录已隔离。

代码或执行失败的候选不接受；版本选择只看 train；本次迭代决策完成后，test 仅用于各脚本的报告评估。
