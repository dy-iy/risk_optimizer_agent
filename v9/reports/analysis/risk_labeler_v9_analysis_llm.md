# 风险标注错误模式分析报告（LLM版）

## 样本规模

- False Positive: 114
- False Negative: 1
- Type Mismatch: 193
- Score Diff Top: 200

## LLM 总结

- score_hack 是误报和类型错误的头号来源，在常规新闻上触发过高分数，导致风险分数严重虚高和主类别错判。
- score_volatility、score_whale 和 score_regulatory 存在明显漏召回，导致许多真实的风险事件被规则系统判定为“无明显风险”。
- score_fraud 的强度映射偏高，对于历史诈骗赔偿类新闻给出过高风险分，但主类别预测尚可。
- score_macro 和 score_liquidation 在非直接加密市场冲击的宏观讨论或非清算事件上过度触发，需要收紧条件。

## 主要错误模式

### 1. score_hack 对非攻击性内容过度触发 [false_positive]

- 影响 scorer: score_hack
- 根因: score_hack 的触发词列表过宽，将“漏洞”“攻击”“批评”等词片面匹配，未考虑上下文安全性（如“不计划”“用户资金未受影响”），且缺少否定模式抑制，导致大量非攻击类文章被高分激活，进而主导主类型选择。
- 优先级: high
- 证据:
  - 误报样本中规则主类别“链上漏洞/攻击风险”出现49次，居首位
  - score_hack 在误报中触发50次，均值0.2858，最大值0.95
  - 样本案例：稳定币需求上升（news_id 315）→ score_hack 0.8856，黄金类型“无明显风险”
  - 样本案例：公司增持比特币（news_id 283）→ score_hack 0.85，黄金类型“无明显风险”
  - 样本案例：Circle CEO 谈 USDC 冻结（news_id 904）→ score_hack 0.9497，黄金类型为“监管与法律风险”，但规则主类型被 score_hack 带偏为“链上漏洞/攻击风险”
- patch 建议:
  - 增加否定排除列表：当内容出现“未受影响”“不计划”“批评”“指责”等词语时，降低或取消 score_hack 分数。
  - 提高触发门槛：要求明确的项目损失金额（>10万美元）或明确的智能合约漏洞报告，否则不给出高于0.5的分数。
  - 增加上下文二次确认规则：若文章主要为声明、采访、政策评论而非实际安全事件，则抑制 score_hack 至 0.2 以下。

### 2. score_volatility 对正常市场活动误判为异常行情 [false_positive]

- 影响 scorer: score_volatility
- 根因: score_volatility 将“创新高”“交易量”“活跃”等中性市场描述误认为异常波动，缺乏对“暴跌”“闪崩”“剧烈回撤”等负面波动词的正向要求。
- 优先级: medium
- 证据:
  - 误报中“异常行情波动风险”出现19次，score_volatility 触发24次
  - 样本：交易量创新高（news_id 324）→ score_volatility 0.45，黄金无明显风险
  - 样本：韩国加密交易份额高（news_id 673）→ score_volatility 0.45，黄金无明显风险
  - 样本：Telegram CEO 批评 WhatsApp 加密（news_id 943）→ score_volatility 0.45，黄金无明显风险
- patch 建议:
  - 收紧触发词：仅当文中出现“暴跌”“闪崩”“价格剧烈波动”“异常波动率”等负面波动信号时才给出高分。
  - 添加正向波动过滤：若描述仅为“增长”“上涨”“交易量提高”而未伴随风险表述，则将分数限制在0.2以下。

### 3. score_macro 误判非加密直接宏观冲击 [false_positive]

- 影响 scorer: score_macro
- 根因: score_macro 对“油价”“冲击”“宏观”等词过于泛化，未要求该冲击直接作用于加密市场（如同时提及比特币价格、加密监管政策），导致普通经济评论被误标。
- 优先级: medium
- 证据:
  - 误报中“宏观/政策冲击风险”出现15次，score_macro 触发19次
  - 样本：油价重塑市场但非直接加密风险（news_id 876）→ score_macro 0.5499，黄金无明显风险
  - 样本：币安高管谈 AI 冲击（news_id 36, 125）→ score_macro 0.45，黄金无明显风险
- patch 建议:
  - 增加加密市场关联条件：要求文章必须提及加密货币/区块链市场影响，否则不触发。
  - 剔除“AI冲击”“重塑投资组合”等不具备直接负面冲击意义的短语，或降低相关权重。

### 4. score_fraud 对历史诈骗赔偿新闻强度过高 [false_positive]

- 影响 scorer: score_fraud
- 根因: score_fraud 对“诈骗”“骗徒”“追回”等词给出最高档强度，没有区分活跃骗局与事后执法/补偿事件，导致历史性安全消息被赋予高风险分。
- 优先级: medium
- 证据:
  - 样本：OneCoin 赔偿申请启动（news_id 884）→ score_fraud 0.88，黄金风险分10，类型正确但分数差大
  - 样本：香港网恋诈骗案追回资金（news_id 935, 536）→ score_fraud 0.88，黄金风险分20-25
- patch 建议:
  - 添加事后类特征降权：当文章提到“赔偿申请”“追回资金”“警方披露”等事后处理行为时，将分数上限限制至0.4。
  - 增加时效性判断：若事件发生在数年前或被定性为历史案件，降低强度评分。

### 5. score_hack 漏掉真实的社会工程攻击事件 [false_negative]

- 影响 scorer: score_hack
- 根因: score_hack 可能因金额小（10万美元）或‘内部’‘未影响用户’等上下文被抑制，未将‘社会工程攻击’‘钱包被盗’纳入强触发模式。
- 优先级: high
- 证据:
  - 唯一漏报案例（news_id 687）：明确描述 AI 社会工程攻击导致内部热钱包被盗，黄金类型“链上漏洞/攻击风险”，规则判定“无明显风险”，score_hack 值为0.2未触发
- patch 建议:
  - 将‘社会工程攻击’‘内部热钱包被盗’‘凭证泄露’等词组加入强触发列表，不受金额限制。
  - 移除将‘用户资金未受影响’作为否定词抑制攻击类分数的逻辑，仅作为减分项而不完全取消。

### 6. score_volatility、score_whale、score_regulatory 真实风险漏判为无明显风险 [type_mismatch]

- 影响 scorer: score_volatility, score_whale, score_regulatory
- 根因: 这些 scorer 的触发条件覆盖不足，许多表达真实风险的文本（如‘最大痛苦点’‘大户出售’‘国会批评’）未能匹配现有关键词，导致分数低于阈值被归类为无明显风险。
- 优先级: high
- 证据:
  - 类型错配对：黄金“异常行情波动风险” → 规则“无明显风险”58次
  - 黄金“大额转账/巨鲸行为风险” → 规则“无明显风险”32次
  - 黄金“监管与法律风险” → 规则“无明显风险”25次
  - 案例：Bitcoin 价格面临最大痛苦点（news_id 8）→ 黄金波动风险，规则无风险
  - 案例：Hyperliquid 巨鲸开仓（news_id 24）→ 黄金巨鲸风险，规则无风险
  - 案例：CFTC 主席面临国会批评（news_id 397）→ 黄金监管风险，规则无风险
- patch 建议:
  - 对 score_volatility：扩展触发词至‘最大痛苦点’‘信任危机’‘回落至…’等市场压力描述。
  - 对 score_whale：增加‘大户’‘巨鲸地址’‘大额转账’‘5倍杠杆’等词，并降低金额门槛（如>50万美元），同时保持对普通买入的抑制。
  - 对 score_regulatory：加入‘国会批评’‘监管阻力’‘法案推进’‘合规门槛’等词，降低对纯投资者调查类文章的触发。

### 7. score_liquidation 在非清算事件上误触发高分数 [score_diff]

- 影响 scorer: score_liquidation
- 根因: score_liquidation 将‘清算’‘杠杆’‘空单’等期货相关术语一概视为风险，未区分平台产品发布或个人投资策略分享与实际清算事件。
- 优先级: medium
- 证据:
  - 分数偏差样本中 score_liquidation 触发26次，均值0.0937
  - 样本：KOL 分享仓位策略（news_id 192）→ score_liquidation 0.45，黄金无明显风险
  - 样本：Bitnomial 推出新期货合约（news_id 547）→ score_liquidation 0.45，黄金无明显风险
- patch 建议:
  - 增加条件：必须有具体的清算价格区间和‘清算强度将达X亿美元’等描述才可给高分。
  - 排除产品介绍和投资策略文章：当文章主体为新品上市或策略分享时，评分上限设为0.2。

## Scorer 级诊断

- **score_hack**: 过宽触发
  - 原因: 在 FP 样本中触发次数最高（50次），均值0.2858，可见大量非攻击类内容被触发；同时唯一 FN 也是因未能识别真实攻击而产生漏召回。
  - 建议: 收紧触发词，增加否定模式，同时强制召回‘社会工程攻击’‘钱包被盗’等明确攻击事件。
- **score_volatility**: 过宽触发 + 漏召回
  - 原因: FP 中触发24次，均值0.0985，但类型错配中真实波动风险漏判58次，说明触发条件既误判了常规市场消息，又未能覆盖真正的波动信号。
  - 建议: 扩大真实波动词的覆盖面，同时限制对‘增长’‘创新高’等中性词的过度触发。
- **score_macro**: 过宽触发
  - 原因: FP 中触发19次，均值0.0832，样本显示‘油价’‘AI冲击’等非直接加密宏观被激活，而黄金宏观风险正确触发很少。
  - 建议: 要求明确提及加密市场影响的证据，否则不触发或压低分数。
- **score_regulatory**: 过宽触发 + 主类别竞争失败
  - 原因: FP 中触发18次，且类型错配里规则将‘监管与法律风险’错误分配给无明显风险文章20次，同时漏判25次真实监管风险。
  - 建议: 增强对具体监管动作（法案、诉讼、罚款）的识别，抑制对泛泛监管话题（调查、态度）的误判。
- **score_whale**: 漏召回
  - 原因: FP 中仅触发9次，类型错配中真实巨鲸风险漏判32次，表明覆盖严重不足。
  - 建议: 扩展触发词至大户活动描述，并降低金额门槛，同时防止将普通公司比特币购买误判为巨鲸风险。
- **score_fraud**: 强度映射偏高
  - 原因: 虽然主类别预测准确，但样本中历史赔偿新闻的分数高达0.88，而黄金风险分仅10-25，表明强度严重偏高。
  - 建议: 为事后、补偿、追回类文本添加强度衰减规则。
- **score_liquidation**: 过宽触发
  - 原因: 在非清算事件（如KOL分享、期货产品上线）触发了较高分数，导致风险评分虚高。
  - 建议: 要求具体的清算金额与价格触发描述，排除产品发布和策略类文章。
- **score_outage**: 证据不足
  - 原因: 触发次数极低，FP中仅4次，无典型样本展示明确问题。
  - 建议: 暂不调整，待累积更多误报案例后再分析。
- **score_solvency**: 证据不足
  - 原因: 触发次数低，类型错配中偿付能力漏判3次，但样本不足，难以确定根因。
  - 建议: 可小幅放宽触发条件进行观察。
- **score_stablecoin**: 证据不足
  - 原因: 仅触发1次，无明确错误模式。
  - 建议: 保持现状。

## patch 顺序

- Step 1: score_hack
  - 动作: 添加否定词库与上下文抑制规则，同时补齐‘社会工程攻击’等漏掉的强触发词，调整阈值使非攻击新闻分数<0.3。
  - 收益: 预计可消除约40%的误报（49例中大部分），并解决唯一的漏报。
- Step 2: score_volatility 与 score_whale
  - 动作: 扩展二者的关键词覆盖以改善漏召回，同时对 score_volatility 增加波动方向过滤，对 score_whale 添加金额门槛。
  - 收益: 类型错配中‘异常行情波动’漏判58次、‘巨鲸风险’漏判32次有望大幅减少。
- Step 3: score_regulatory
  - 动作: 细化触发条件，增加具体监管动作词，排除纯调查或态度类新闻，并优化与 score_hack 的竞争关系。
  - 收益: 纠正约25次真实监管风险漏判与20次假监管风险错配。
- Step 4: score_macro 与 score_fraud
  - 动作: 对 score_macro 添加加密市场关联强制要求；对 score_fraud 添加事后处理降权规则。
  - 收益: 减少约15次宏观误报，并使诈骗相关风险分数与实际风险等级匹配。
- Step 5: score_liquidation
  - 动作: 增加清算金额阈值，排除产品发布/策略类文章。
  - 收益: 减少由分数偏高导致的误报，稳定清算风险评级。

**整体置信度**: high
