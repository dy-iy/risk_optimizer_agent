# 风险标注错误模式分析报告（LLM版）

## 样本规模

- False Positive: 84
- False Negative: 2
- Type Mismatch: 230
- Score Diff Top: 200

## LLM 总结

- score_hack 与 score_macro 是最主要的误报来源，大量安全讨论和宏观评论被误判为高风险，导致 false positive 高发
- 多个 scorer（score_volatility、score_regulatory、score_solvency）存在过宽触发和强度映射偏高，同时真实风险类型（异常行情、监管、巨鲸）被大量漏报，主类别选择严重偏向“无明显风险”

## 主要错误模式

### 1. score_hack 对安全讨论、漏洞披露和无关内容的过度触发 [false_positive]

- 影响 scorer: score_hack
- 根因: score_hack 关键词宽泛（如“漏洞”“攻击”“黑客”等），未区分积极安全运营、漏洞披露、AI 安全讨论与真实攻击事件，缺少否定词和上下文过滤
- 优先级: high
- 证据:
  - false_positive 中规则主类别为“链上漏洞/攻击风险”达 37 次，gold 主类别为“无明显风险”达 35 次
  - score_hack 在误报中触发 38 次，mean 0.268，max 0.95
  - 样本示例：news_id 167（Ondo Bridge 安全运营无损失）score_hack=0.7，news_id 235（JENNER Meme 不被视为证券）score_hack=0.85，均被误标为高风险攻击
- patch 建议:
  - 增加否定条件词表：如“安全运营”“无资金损失”“无异常事件”“抵御”“加固”等，命中后降低触发权重或直接抑制触发
  - 对纯漏洞报告、安全合作、资助项目等非攻击文本设定较低强度上限，并避免其成为主类别
  - 将“加密安全”“AI安全”等中性讨论从高分区间排除，转移到低风险或无风险

### 2. score_macro 对宏观经济评论和长期展望的误触发 [false_positive]

- 影响 scorer: score_macro
- 根因: score_macro 将关于地缘政治、金融系统、央行代币化等分析师评论和长期展望视为即时政策冲击风险，缺乏对风险事件性质的判断
- 优先级: high
- 证据:
  - 误报中规则主类别“宏观/政策冲击风险”出现 11 次，gold 仅 3 次
  - score_macro 触发 11 次，mean 0.0768，max 0.5593
  - 样本：news_id 749（比特币吸引力与地缘政治碎片化）、news_id 5（何一谈 AI 与金融基建）、news_id 71（Palantir 书讨论）均被标为宏观风险且得分 0.5 以上
- patch 建议:
  - 收紧触发条件：要求存在明确的政策发布、紧急声明或突发宏观事件，排除分析师评论、观点文章和长期展望
  - 引入文本类型判别：若包含“分析师表示”“指出”“讨论”“展望”等词，降低 score_macro 输出
  - 提高主类别竞争所需的最低分数阈值（例如 0.6），避免低分宏观成为主类型

### 3. score_volatility 对常规市场行情的过度反应 [false_positive]

- 影响 scorer: score_volatility
- 根因: score_volatility 将板块涨跌、交易量变化等普通市场动态视为异常波动，缺乏波动幅度阈值和异常程度判断
- 优先级: high
- 证据:
  - 误报中“异常行情波动风险”规则类型 7 次，gold“无明显风险”5 次
  - score_volatility 触发 8 次，mean 0.0611，max 0.7499
  - 样本：news_id 368（AI 板块上涨）score_volatility=0.7499，news_id 956（市场涨跌互现）0.6，均为日常行情报道
- patch 建议:
  - 引入波动幅度门槛：仅当单币种或整体市场出现大幅暴跌/暴涨（如超 30%）时触发高分，普通涨跌使用低分或不触发
  - 排除常见行情标题模板，如“X板块上涨”“市场涨跌互现”“小幅下跌”等，降低对应文本权重
  - 增加否定词/弱化词：“小幅”“微涨”“震荡”出现时抑制触发

### 4. 真实风险类别被“无明显风险”淹没，严重漏报 [type_mismatch]

- 影响 scorer: score_volatility, score_regulatory, score_whale, score_team, score_infra
- 根因: 相关 scorer 触发阈值偏高、关键词覆盖不足，且主类别选择逻辑倾向于在多个 scorer 均未明显触发时回退为“无明显风险”
- 优先级: high
- 证据:
  - mismatch pair：异常行情→无明显风险 56 次，监管→无明显风险 37 次，大额转账/巨鲸→无明显风险 25 次
  - 规则输出“无明显风险”高达 154 次，而 gold 仅 48 次
  - 样本：news_id 8（Bitcoin价格高于最大痛苦点）gold异常行情→规则无明显风险，news_id 83（韩国数字资产立法延迟）gold监管→无明显风险
- patch 建议:
  - 大幅扩充异常行情、监管、巨鲸等漏报严重 scorer 的关键词和语义模式，降低最低触发门槛
  - 调整主类别选择逻辑：当多个 scorer 给出微弱信号时，仍可按照二级规则合并归为某一风险类型，而非直接判无风险
  - 为易漏类别设置“疑似风险”兜底策略，当满足弱条件时予以标记并提升风险分

### 5. score_regulatory 与 score_solvency 强度映射偏高，导致高分低风险 [score_diff]

- 影响 scorer: score_regulatory, score_solvency
- 根因: scorer 未对事件严重程度进行分级，将一般监管动态、代币化讨论与重大危机同等赋值，导致得分远超真实风险水平
- 优先级: medium
- 证据:
  - 样本 news_id 120（中国金融法草案咨询）score_regulatory=0.8，gold=35；news_id 423（巴拉圭逮捕洗钱团伙）同样高分低风险
  - 样本 news_id 863（欧洲央行代币化报告）score_solvency=0.88，gold=25；news_id 575（摩根士丹利谈代币化）score_solvency=0.78，gold=0
  - score_solvency 触发 12 次在 score_diff 样本中，mean 0.0518，但峰值达 0.88
- patch 建议:
  - 为 score_regulatory 建立严重性阶梯：法律草案、提案、征求意见等低档，罚款、逮捕、禁令等高档，分数随之调整
  - 为 score_solvency 聚焦真实偿付危机关键词（如资不抵债、储备不足、冻结提现），降低对代币化、增持等中性讨论的敏感度
  - 重新校准这些 scorer 的分数映射，确保低风险文本输出较低分值（如 0.4 以下）

### 6. 漏洞报告与事后黑客地址处理未充分触发 score_hack [false_negative]

- 影响 scorer: score_hack
- 根因: score_hack 侧重攻击行为关键词，对“漏洞”“冻结”等事前预防或事后响应信号捕获不足，且触发阈值可能偏高
- 优先级: medium
- 证据:
  - 漏报样本 news_id 797（Saturn 协议严重漏洞）gold=85，rule=25，top_triggered_scores 为空
  - 漏报样本 news_id 373（Tether 冻结黑客地址）gold=70，rule=25，top_triggered_scores 为空
  - false_negative 中 score_hack 未触发，mean=0.25，低于触发阈值
- patch 建议:
  - 新增漏洞风险关键词：如“严重漏洞”“脆弱性”“提款冻结漏洞”“资金冻结风险”，并将其映射到中等攻击风险
  - 将黑客地址冻结、资金拦截、威胁情报等作为攻击事件衍生信号，赋予一定分数
  - 适当降低 score_hack 触发阈值，或增加针对漏洞与补救事件的专属规则分支

## Scorer 级诊断

- **score_hack**: 过宽触发 / 漏召回
  - 原因: 误报中触发最频繁（38次），将安全正面消息和无关讨论判为攻击风险；同时对于严重漏洞报告和黑客地址冻结存在漏报
  - 建议: 收紧关键词并增加否定词；扩展漏洞和事后处理覆盖，降低触发阈值并建立强度分层
- **score_macro**: 过宽触发
  - 原因: 11次误触发，对宏观评论、分析师展望和长期讨论过于敏感，且强度直接拉高导致误报
  - 建议: 限制触发场景为突发政策事件或紧急声明，增加观点/分析文本抑制规则，提高主类别竞争阈值
- **score_volatility**: 过宽触发
  - 原因: 8次误触发，将日常板块涨跌、交易量变化视为异常波动，缺乏异常度判断
  - 建议: 设置波动幅度门槛，过滤常规行情报道，引入小幅波动抑制词，降低普通行情得分
- **score_regulatory**: 强度映射偏高
  - 原因: 触发次数不多（9次），但每次得分偏高（max 0.8），导致 gold 低风险被标为高风险
  - 建议: 建立监管事件严重度分级，降低一般法规进展、提案咨询的分数，仅重大执法行动给予高分
- **score_solvency**: 过宽触发 / 强度映射偏高
  - 原因: 误报6次，将代币化、增持、流动性讨论误判为偿付能力危机，且分数偏高（max 0.88）
  - 建议: 聚焦真实偿付危机关键词（如挤兑、资不抵债、冻结提现），对普通代币化、储备讨论降低敏感度并重新校准分数
- **score_whale**: 漏召回
  - 原因: type mismatch 中巨鲸风险25次被漏报为无明显风险，触发次数极少（5次误报中），说明对大户行为信号捕捉不足
  - 建议: 扩充巨鲸行为关键词（如大额转账、巨鲸地址、持仓异动），降低触发门槛，增加对持仓变化、大单操作的响应
- **score_team**: 漏召回
  - 原因: gold 中“项目治理/团队异常风险”出现10次，但规则几乎未触发该类型，trigger_count仅1次
  - 建议: 增加团队异动、治理风险关键词（如团队离职、控制权变更、治理攻击），建立独立触发分支
- **score_infra**: 漏召回
  - 原因: gold 基础设施/协议层异常风险出现7次，但规则触发为0次，完全未能捕获此类风险
  - 建议: 补充基础设施和协议层异常的关键词（如网络中断、分叉、协议漏洞、节点故障），建立基础触发
- **score_liquidation**: 证据不足
  - 原因: 误报3次，gold爆仓/清算风险出现量不大，存在少量漏报但整体影响有限
  - 建议: 可观察是否需要增强爆仓相关信号，暂无需紧急修改
- **score_stablecoin**: 证据不足
  - 原因: 触发次数极少，误报和漏报数量均较小，暂无明显模式
  - 建议: 继续监控，若稳定币风险事件增多再考虑优化

## patch 顺序

- Step 1: score_hack
  - 动作: 增加否定词和上下文过滤，区分安全运营、漏洞披露与真实攻击；同时扩展漏洞与事后处理关键词，降低触发阈值
  - 收益: 大幅减少攻击类误报（~37例），同时缓解漏报问题
- Step 2: score_volatility 与 score_macro
  - 动作: 收紧触发条件，增加波动幅度阈值和观点文本抑制，降低这两类在日常行情和宏观评论中的误触发
  - 收益: 显著降低异常行情与宏观类误报，减少类型错配（异常行情→无明显风险错配56例中部分改善）
- Step 3: 主类别选择逻辑
  - 动作: 调整回退策略，允许在多个弱信号下仍输出具体风险类型，降低“无明显风险”的占比
  - 收益: 直接改善类型错配（230例），使监管、巨鲸、异常行情等真实风险被正确分类
- Step 4: score_regulatory 与 score_solvency
  - 动作: 建立严重性分级，重新映射分数强度，降低一般动态得分
  - 收益: 减少高分低风险误报，优化 score_diff 分布
- Step 5: score_whale、score_team、score_infra
  - 动作: 扩充关键词、降低触发门槛，提升对这些风险类型的召回
  - 收益: 减少巨鲸、团队、基础设施风险的漏报，降低类型错配

**整体置信度**: high
