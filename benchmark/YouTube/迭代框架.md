# YouTube LF 迭代框架

本任务使用 [Benchmark 统一流程](../README.md)，运行命令和输出约定见 [README.md](README.md)。

1. 直接使用 WRENCH 固定提交 `d1185f6cfba8d5ace2a39229799cb3f1c136bf66` 的 `classification/youtube/train.json`、`valid.json`、`test.json`：train 1,686 条、valid 120 条、test 250 条。正文、顺序和样本归属逐条一致，不按原 CSV 重抽，不去重、不重新分组。
2. 标签为 `0=ham、1=spam`，LF 弃权为 `-1`。负面情绪、非英语和粗俗用语本身不构成垃圾评论；判断推广、自我引流、诈骗和无关广告。
3. 训练集只保存 `id,text`，验证集和测试集保存 `id,text,label`；编号是 `youtube_<split>_<官方编号>`。不导入官方训练金标或预定义弱标签。源文件及 CSV 的 SHA256、固定提交和条数写入 `data/split.json`；后续离线校验和复用，不静默重建。
4. 冷启动规则位于 `versions/v1/lfs.py`。已有训练和迭代记录保留原内容。
5. 起点由用户指定，先评价起点，再追加指定轮数。0 轮只评价，不调用 LLM；支持交互和命令行参数。
6. 同一批 LF 投票分别用于 Snorkel 和简单投票。Snorkel 仅拟合训练投票，CPU、500 epochs、seed 42；先验由完整验证集的类别比例估计，计入监督预算。简单投票等权，平票或全弃权时弃权，不使用先验。
7. Analyzer 接收当前 LF 完整代码、简单投票在 120 条验证集上的整体指标、按类别已覆盖/未覆盖数量、训练覆盖/冲突统计及每个 LF 的质量。验证错例、弃权和正确样例按简单投票预测划分，训练未覆盖和训练冲突按原始投票划分。每组按版本和 seed 42 抽取最多 30 条，训练样例不附金标。
8. 测试正文、标签、预测和指标只用于最终评估。`tools/feedback.py` 构造本轮反馈，工作流补充连续被拒的方案和净收益变化，再保存到候选版本的 `results/feedback.json`。
9. Analyzer 返回统一的 `action`、`summary`、`operations`，每轮只选择新增、修改或删除一种操作。训练集或验证集 LF 覆盖率低于 0.8 时优先改善覆盖；覆盖上下文由程序计算，不要求模型重复生成。解析或业务校验失败时，原 Analyzer 接收原回复和具体错误，最多纠正一次。
10. Patcher 只输出计划中的目标函数，由本地按源码位置合并。每轮最多操作 5 个 LF，至少保留三个；AST 校验实际操作与计划一致。删除在本地完成，不调用 Patcher。
11. LF 是普通 `def lf_name(text)`，返回整数 -1/0/1；只允许局部文本处理，不访问文件、网络、环境变量、样本编号或金标，不将整句抄成标签查表。
12. 生成校验与候选运行共用一次 LF 技术修复额度，每轮重置，修复仍相对本轮原始代码计数。两次失败停止并保留候选和错误；API/文件错误直接停止。错误反馈不包含测试正文或编号。
13. 每版记录验证和测试的覆盖率、全量/已覆盖准确率、两类 P/R/F1、Macro-F1 和混淆矩阵，以及训练覆盖/冲突和 LF 质量。全量指标包含弃权；LF 全弃权或聚合最高概率并列时保留 -1，导出为 `abstain`。
14. 以 Snorkel 的验证集净收益验收。默认提升须严格大于 0.01，通过后才更新保留版。拒绝后从保留版继续，连续拒绝 3 次则停止。
15. 候选编号使用现有最大版本号加一。`results/` 保存候选的反馈、分析、共享投票、质量和 `decision.json`；`Snorkel/` 和 `simple_vote/` 分别保存指标、弱标签和修改影响。分析和 LF 修复分别保留首次与纠正回复。
16. `metrics.json` 保存 WRENCH 数据提交、集合条数和 CSV 哈希；绘图只使用与当前划分一致的结果，PNG/SVG 分别输出到 `picture/Snorkel/` 和 `picture/simple_vote/`。修改影响仅比较训练与验证集，不进入模型反馈，不触发自动回退。
17. 每次真实 Analyzer/Patcher/修复调用按 API 返回记录 Token，区分本次和历史，未知值留空；离线验证和零轮评价不计为 API 调用。

反复使用同一固定验证集可能对开发样本过拟合，最终效果由测试集报告。运行命令和实验起点说明见 `README.md`。
